# 启动弹窗修复与复测

启动入口仍为「启动应用」。仅运行这一项即可，它会继续进入「启动游戏」。

## 当前处理

- 首次等待登录或主页最多 80 秒。
- 活动中心：识别左上标题（阈值 0.9），点击用户确认的左上圆形返回按钮，目标为 1280×720 坐标 `[52,38,22,22]`。不再匹配活动背景里的白色装饰。关闭后继续检查，只有主页确认通过才成功。
- 活动宣传图：同时识别背景上的日历、每日任务图标，并确认这两处有暗色遮罩，再点击左下角图外区域。点击位置为框架 1280×720 坐标 `[90,640,30,25]`。
- 每次关闭后重新识别，不预设宣传图张数；最多进入 20 次后续界面检查，每次等待最多 10 秒。超过次数或识别超时按失败停止，不盲点。
- 完成启动：日历、每日任务图标及两处无遮挡亮度同时命中，等待 1.2 秒后再次检查。确认期间新出现的活动图或活动中心仍能进入关闭分支。
- 原有登录、协议、领取奖励分支继续返回界面检查，每个分支最多命中 5 次。其他日常使用的返回节点保留。

## 已验证与限制

官方 JSON Schema、任务引用及模板依赖检查通过。新增模板从用户提供截图按 1280×720 缩放后裁剪。

用三张用户截图在参考位置做灰度归一化相关性及 RGB 像素数量对照：主页仅通过主页判据，活动图仅通过活动图判据，活动中心仅通过活动中心判据。活动图后方两个主页图标的相关性为 0.9947、0.9997，说明单纯匹配图标会误判，必须结合亮度。

该离线对照不是 MaaFramework 真机识别测试。当前素材来自聊天截图，缩放编码与模拟器采集可能有差异；若实测失败，应使用扩展采集的短边 720 原图更新模板。不同布局或覆盖底部图标的活动图可能无法识别，此时会停止而非盲目点击。

## 复测步骤

1. 在 VS Code 保存文件；停止旧任务。必要时重新加载窗口，让扩展重新读取资源。
2. 模拟器停在活动图上，任务列表只保留「启动应用」，点击 Start。
3. 日志应依次出现「关闭启动活动图」（可多次）、「关闭启动活动中心」（可选）、「完成启动」、「完成启动_确认」。
4. 再从干净主页运行一次，应直接完成而不点击游戏。
5. 最后关闭游戏后重新运行「启动应用」，覆盖完整启动过程。

如失败，记录失败节点、当前游戏截图及该节点原始数据。不要通过降低阈值掩盖状态判断错误。
